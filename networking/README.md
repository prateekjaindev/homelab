# Part 2: Networking

Companion to Part 2 of the Cybertron series: Cilium replaces Flannel and
kube-proxy on the running cluster, then LoadBalancer IPs on the LAN, two
Gateways (LAN and internet), Let's Encrypt certificates for LAN-only names,
and one Cloudflare Tunnel for public apps.

```
                       Internet
                          │
                   Cloudflare edge        TLS for *.prateek.cloud
                          │  outbound-only tunnel, no port forwarding
 ┌────────────────────────┼─────────────── CYBERTRON ──────────────┐
 │                 cloudflared ×2                                  │
 │                        │ http                                   │
 │                 Gateway "public"        Gateway "internal" ◄──── 192.168.1.201
 │                 *.prateek.cloud         *.lab.prateek.cloud     │  LAN, HTTPS
 │                        │                       │                │
 │                   public apps          lab apps, dashboards     │
 │                                                                 │
 │  Cilium: pod network · kube-proxy replacement · NetworkPolicy · │
 │          LB IPAM + L2 announcements · Gateway API · Hubble      │
 │  cert-manager: *.lab.prateek.cloud, Let's Encrypt DNS-01        │
 └─────────────────────────────────────────────────────────────────┘
```

Replace `prateek.cloud` with your domain and the `192.168.1.x` addresses with
your network. Run the commands from the repository root, in bash.

## Before you start

Tools: `talosctl`, `kubectl`, `helm`, the Cilium and Hubble CLIs, and
`cloudflared`.

```bash
talosctl -n 192.168.1.111 etcd snapshot etcd-before-cilium.db
```

The LoadBalancer IPs (`192.168.1.201–205`) must never be handed out by the
router's DHCP server: shrink the DHCP range, or reserve each address with a
DHCP binding to a placeholder MAC (`02:00:00:00:02:01` …), like the API VIP
in Part 1. Check nothing uses them:

```bash
for i in $(seq 201 205); do ping -c1 -W1 192.168.1.$i >/dev/null && echo "192.168.1.$i is in use"; done
```

## Migrating to Cilium

Gateway API CRDs first, so Cilium creates its `cilium` GatewayClass:

```bash
kubectl apply --server-side -f \
  https://github.com/kubernetes-sigs/gateway-api/releases/download/v1.6.1/standard-install.yaml
```

Tell Talos to stop managing Flannel and kube-proxy, on all three nodes
before deleting anything. Check which config format your nodes use first
(`talosctl get machineconfig -o jsonpath='{.spec}' | grep '^kind:'`); this
patch is for configs without a `KubeFlannelCNIConfig` document:

```bash
talosctl -n 192.168.1.111 patch machineconfig --patch @networking/talos/cilium.yaml --mode=no-reboot --dry-run
talosctl -n 192.168.1.111,192.168.1.112,192.168.1.113 patch machineconfig \
  --patch @networking/talos/cilium.yaml --mode=no-reboot
talosctl -n 192.168.1.111,192.168.1.112,192.168.1.113 get manifests   # no 05-flannel, no 10-kube-proxy
```

Talos doesn't delete what it already deployed:

```bash
kubectl -n kube-system delete daemonset kube-flannel kube-proxy
kubectl -n kube-system delete configmap kube-flannel-cfg
kubectl -n kube-system delete serviceaccount flannel kube-proxy
kubectl delete clusterrolebinding flannel kube-proxy
kubectl delete clusterrole flannel
```

Install Cilium straight away:

```bash
helm repo add cilium https://helm.cilium.io/
helm install cilium cilium/cilium --version 1.20.2 \
  --namespace kube-system --values networking/cilium/values.yaml
kubectl -n kube-system rollout status ds/cilium --timeout=10m
```

Reboot one node at a time to clear Flannel's interfaces and kube-proxy's
iptables rules (run the health check from a node that isn't rebooting):

```bash
talosctl -n 192.168.1.113 reboot
kubectl wait --for=condition=Ready node/ratchet --timeout=10m
talosctl health --nodes 192.168.1.111
talosctl -n 192.168.1.113 get links | grep -E "cni0|flannel"   # no output

# then bumblebee (.112) and optimus (.111, health check from .112)
```

Verify:

```bash
kubectl get pods -n kube-system -o wide --field-selector=status.phase=Running
kubectl -n kube-system exec ds/cilium -c cilium-agent -- cilium-dbg status

kubectl delete pods -A --field-selector=status.phase=Failed   # records of pods that ran during the reboots
cilium connectivity test --cleanup
cilium connectivity test --namespace-labels pod-security.kubernetes.io/enforce=privileged
cilium connectivity test --cleanup
```

## LoadBalancer IPs: LB IPAM and L2 announcements

```bash
kubectl apply -f networking/cilium/lb-ipam.yaml
kubectl get ciliumloadbalancerippool
kubectl apply -f networking/demo/whoami-lb.yaml
kubectl -n demo get svc whoami-lb

```

To reach it from the LAN, lift both demo policies for a moment, then clean up:

```bash
kubectl -n demo delete networkpolicy deny-all-ingress
kubectl -n demo delete ciliumnetworkpolicy allow-from-gateway
curl http://192.168.1.205
kubectl -n demo delete svc whoami-lb
kubectl apply -f networking/demo/deny-all.yaml -f networking/demo/allow-from-gateway.yaml
```

## Real certificates for LAN-only names

Cloudflare API token: "Edit zone DNS" template, limited to your zone.

```bash
helm install cert-manager oci://quay.io/jetstack/charts/cert-manager \
  --version v1.21.2 --namespace cert-manager --create-namespace \
  --values networking/cert-manager/values.yaml
kubectl -n cert-manager rollout status deploy/cert-manager-webhook

read -rs CF_API_TOKEN
kubectl -n cert-manager create secret generic cloudflare-api-token \
  --from-literal=api-token="$CF_API_TOKEN"
unset CF_API_TOKEN

sed 's/<your-email>/you@example.com/' networking/cert-manager/cluster-issuers.yaml | kubectl apply -f -
kubectl get clusterissuer                     # both READY True

kubectl apply -f networking/gateway/namespace.yaml
kubectl apply -f networking/cert-manager/lab-wildcard-staging.yaml
kubectl -n gateway get certificate -w         # READY True
kubectl -n gateway delete certificate lab-wildcard-staging
kubectl -n gateway delete secret lab-wildcard-staging-tls

kubectl apply -f networking/gateway/lab-wildcard.yaml
kubectl -n gateway get certificate lab-wildcard -w
```

## The public Gateway and one shared Cloudflare Tunnel

```bash
kubectl apply -f networking/gateway/public.yaml

cloudflared tunnel login
cloudflared tunnel create cybertron           # prints the tunnel ID
export TUNNEL_ID=<id>
kubectl apply -f networking/cloudflared/cloudflared.yaml
kubectl -n cloudflared create secret generic cloudflared-cybertron \
  --from-file=credentials.json="$HOME/.cloudflared/$TUNNEL_ID.json" \
  --from-literal=TUNNEL_ID="$TUNNEL_ID"
kubectl -n cloudflared rollout restart deploy/cloudflared
cloudflared tunnel info cybertron
```

External and isolation tests:

```bash
kubectl label namespace demo gateway.cybertron/public=true
kubectl apply -f networking/demo/route-public.yaml
```

## Breaking it on purpose

```bash
# which node answers for .201
kubectl -n kube-system get lease cilium-l2announce-gateway-cilium-gateway-internal \
  -o jsonpath='{.spec.holderIdentity}{"\n"}'

# terminal 1
while true; do printf '%s ' "$(date +%T)"; curl -s --max-time 2 https://whoami.lab.prateek.cloud | grep ^Hostname || echo FAIL; sleep 0.5; done
# terminal 2
kubectl -n kube-system get lease cilium-l2announce-gateway-cilium-gateway-internal -w \
  -o custom-columns='HOLDER:.spec.holderIdentity,TRANSITIONS:.spec.leaseTransitions,RENEWED:.spec.renewTime'
# terminal 3: reboot the holder
talosctl -n <holder-ip> reboot
```

Tunnel connector: run the same loop against `https://whoami.prateek.cloud`
and delete one pod in `cloudflared`.

## Rollback

If Cilium never becomes ready: `helm uninstall cilium -n kube-system`, revert
the patch on all three nodes
(`talosctl patch mc --patch '[{"op":"remove","path":"/cluster/network/cni"},{"op":"remove","path":"/cluster/proxy/disabled"}]'`),
check `talosctl get manifests` lists Flannel and kube-proxy again, then
reboot the nodes one at a time. For anything worse, restore the etcd
snapshot with the Talos disaster-recovery guide.
