# Part 4: Importing the cluster into Omni

Companion to Part 4 of the Cybertron series,
[Importing an Existing Talos Cluster into Omni](https://blog.prateekjain.dev/bb1fc7722eda?source=friends_link&sk=a4c4412829ef81542ca4892a0edbecec).

The running cluster is handed to Sidero Omni's free hosted Hobby plan without a rebuild. Omni
imports the nodes, keeps their config as patches, and from then on kubectl and talosctl go
through Omni with single sign-on. Both CAs are rotated at the end, so the talosconfig and
kubeconfig from Part 1 stop working.

```
  laptop ── kubectl, talosctl (OIDC login) ──► Omni (hosted)
                                                 ▲
                                                 │  SideroLink: WireGuard, opened by each node,
                                                 │  outbound only, no ports open at home
 ┌───────────────────── HOME LAN · CYBERTRON ────┼──────────────────┐
 │   optimus .111      bumblebee .112      ratchet .113             │
 │   VIP .200 stays on the nodes; the Kubernetes endpoint moves to  │
 │   Omni's SideroLink address                                      │
 └──────────────────────────────────────────────────────────────────┘
```

Replace the `192.168.1.x` addresses, the machine IDs and the hostnames with yours. Run the
commands from the repository root, in bash.

## Versions

| Component | Version |
| --- | --- |
| Talos | 1.14.0 (machine config generated by talosctl 1.13.9) |
| Kubernetes | 1.36.3 |
| omnictl | 1.12.4 |
| Omni plan | Hobby (free, hosted) |

## Files

| File | What it is |
| --- | --- |
| `patches/<node>.yaml` | Replacement for the patch the import creates for each node, written with the Talos 1.14 documents |
| `undo.yaml` | Removes the three documents the import adds to a node, for an abort before unlocking |

## 1. Check the cluster and back it up

```bash
talosctl -n 192.168.1.111 health --control-plane-nodes 192.168.1.111,192.168.1.112,192.168.1.113
talosctl -n 192.168.1.111 etcd members
kubectl get nodes -o wide
```

Keep a copy of the current talosconfig, kubeconfig and secrets outside git.

## 2. Install the tools and sign in

```bash
brew install siderolabs/tap/sidero-tools   # macOS or Linux with Homebrew
yay -S omnictl-bin kubelogin               # Arch (kubelogin is the oidc-login plugin)
mkdir -p ~/.talos/omni
cp ~/Downloads/omniconfig.yaml ~/.talos/omni/config
omnictl get clusters
```

`omniconfig.yaml` comes from the **Download omnictl** button in the Omni dashboard.

## 3. Import, locked

```bash
omnictl cluster import \
  --talosconfig ~/cybertron/talosconfig \
  --nodes 192.168.1.111,192.168.1.112,192.168.1.113 \
  --talos-version v1.14.0 \
  --kubernetes-version v1.36.3 \
  --initial-talos-version v1.13.9 \
  --initial-kubernetes-version v1.36.3 \
  --dry-run
```

Run it again without `--dry-run`, adding `-O ~/cybertron/omni-import-backup.zip`. The backup
holds every node's full machine config, secrets included. The cluster is now in Omni and locked.

## 4. Rewrite the patches for Talos 1.14

Omni builds the config in the style of the Talos version the cluster runs now and lays the
imported patch on top. A cluster created by talosctl 1.13 gets Flannel and kube-proxy next to
Cilium and a control-plane taint on every node. Look at **Pending Updates** in the Omni UI, then
replace the imported patches (same IDs) while the cluster is still locked:

```bash
omnictl get configpatches
omnictl apply -f omni/patches/optimus.yaml
omnictl apply -f omni/patches/bumblebee.yaml
omnictl apply -f omni/patches/ratchet.yaml
omnictl get machinependingupdates -o yaml | grep -c -E "KubeFlannelCNIConfig|KubeProxyConfig|SecurityProfileConfig|NoSchedule"
```

The last command should print `0`.

To back out instead, while the cluster is still locked:

```bash
omnictl cluster import abort cybertron
talosctl -n 192.168.1.111,192.168.1.112,192.168.1.113 patch machineconfig --patch @omni/undo.yaml
```

## 5. Unlock and restart what talks to the API

```bash
omnictl cluster unlock cybertron
curl -sk https://192.168.1.200:6443/readyz
```

The service account issuer moves to Omni's address, so pods holding old tokens get
`Unauthorized`. Restart them:

```bash
kubectl -n kube-system rollout restart daemonset cilium
kubectl -n kube-system rollout status daemonset cilium
kubectl -n kube-system rollout restart deployment cilium-operator coredns hubble-relay metrics-server
kubectl -n cert-manager rollout restart deployment
```

## 6. kubectl and talosctl through Omni

```bash
omnictl kubeconfig --cluster cybertron
omnictl talosconfig --cluster cybertron
export TALOSCONFIG=~/.talos/config
kubectl get nodes
talosctl -n 192.168.1.111 version
```

## 7. Rotate both CAs

```bash
omnictl cluster -n cybertron secret rotate talos-ca
omnictl cluster -n cybertron secret rotate kubernetes-ca
omnictl cluster -n cybertron secret rotate status
```

Pods keep the old cluster CA, so run the restarts from step 5 again. Then check that the old
files are rejected:

```bash
talosctl --talosconfig ~/cybertron/talosconfig -n 192.168.1.111 version
kubectl --context admin@cybertron get nodes
```
